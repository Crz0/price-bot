# بوت متابعة أسعار المنتجات (تيليجرام)

بوت مجاني بالكامل يتابع سعر منتج معيّن على نون / أمازون السعودية /
إكسترا، ويرسل لك تنبيه في تيليجرام أول ما يلقى سعر أرخص من آخر مرة.

## المعمارية باختصار

- **المشغّل (scheduler):** GitHub Actions، مجاني بالكامل (بدون حدود
  دقائق لو الريبو **عام/Public**)، يشتغل كل 30 دقيقة تلقائياً.
- **قاعدة البيانات:** ملفات JSON داخل `data/` نفس الريبو — الـ
  workflow يعمل commit لها بعد كل تشغيل. ما فيه سيرفر ولا قاعدة
  بيانات خارجية.
- **البوت:** يستخدم "polling" (`getUpdates`) بدل "webhook" — يعني كل
  ما يشتغل الـ workflow، يسأل تيليجرام "فيه رسائل جديدة؟" ويعالجها،
  بعدها يفحص الأسعار.

**نقطة مهمة:** بما إنه مجدول كل 30 دقيقة، الأوامر (`/add`, `/list`,
`/remove`) ما ترد عليك بشكل فوري لحظة الإرسال — تنتظر لحد أقرب
تشغيلة. تقدر دايماً تشغّله يدوياً من تبويب **Actions** بالريبو
(زر "Run workflow") لو ما تبي تنتظر.

## خطوات النشر من الصفر

### 1. أنشئ بوت تيليجرام
1. افتح تيليجرام وابحث عن `@BotFather`.
2. أرسل `/newbot` واتبع التعليمات (اسم البوت + username ينتهي بـ `bot`).
3. راح يعطيك **توكن** شكله مثل `123456789:ABCdefGhIJKlmNoPQRstuVwxyz`.
   احفظه، بتحتاجه بالخطوة 3.
4. افتح محادثة مع بوتك وأرسل له أي رسالة (مثلاً "هلا") — هذا يخلي
   تيليجرام يسجل إنك بدأت محادثة معه (بدونه ما يقدر يرسل لك).

### 2. ارفع الكود على GitHub
1. أنشئ حساب GitHub لو ما عندك.
2. أنشئ **ريبو جديد Public** (عام) — مهم يكون Public عشان GitHub
   Actions يكون مجاني بدون حدود دقائق شهرية.
3. ارفع كل ملفات هذا المشروع للريبو (تقدر تسحب الملف المضغوط اللي
   جهزته لك وترفعه، أو تستخدم git):
   ```bash
   git init
   git add .
   git commit -m "بوت متابعة الأسعار"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```

### 3. أضف الأسرار (Secrets)
داخل الريبو: **Settings → Secrets and variables → Actions → New
repository secret**

أضف أول سر بس بالبداية:
- `TELEGRAM_BOT_TOKEN` = التوكن اللي أخذته من BotFather

(سر ثاني `TELEGRAM_AUTHORIZED_CHAT_ID` بتضيفه بالخطوة الجاية بعد ما
تعرف رقم الشات حقك).

### 4. شغّل البوت أول مرة وعرف رقم الشات (chat_id) حقك
1. روح لتبويب **Actions** بالريبو → اختر workflow اسمه
   "Price Check Bot" → زر **Run workflow** لتشغيله يدوياً.
2. البوت أول ما يشتغل وما يلقى `TELEGRAM_AUTHORIZED_CHAT_ID`
   معبّى، بيرد على أي رسالة أرسلتها له بالخطوة 1.4 برقم الشات حقك.
3. روح لتيليجرام وشوف رد البوت — انسخ الرقم.
4. رجع لـ GitHub Secrets وأضف سر جديد:
   - `TELEGRAM_AUTHORIZED_CHAT_ID` = الرقم اللي نسخته
   (هذا يمنع أي شخص ثاني غيرك يتحكم بالبوت لو صدفة لقى الـ username حقه)

### 5. تأكد إن الجدولة التلقائية شغالة
GitHub أحياناً يوقف تلقائياً الـ scheduled workflows لو الريبو ما
فيه أي نشاط لمدة 60 يوم. لو لاحظت إن البوت وقف يرد بدون سبب، روح
لتبويب Actions وشغّله يدوياً مرة عشان "يصحّي" الجدولة.

### 6. جرّبه
أرسل لبوتك بتيليجرام:
```
/add ايفون 16 برو 256 جيجا
```
وانتظر أقرب تشغيلة (أو شغّلها يدوياً من Actions). بعدها جرّب:
```
/list
/remove 1
/help
```

## هيكل المشروع

```
telegram-price-bot/
├── bot/
│   ├── config.py          # قراءة الإعدادات من متغيرات البيئة
│   ├── telegram_api.py    # اتصال بسيط بـ Telegram Bot API
│   ├── storage.py         # قراءة/كتابة ملفات JSON
│   ├── commands.py        # منطق /add /list /remove
│   ├── main.py             # نقطة التشغيل (يستدعيها الـ workflow)
│   └── scrapers/
│       ├── base.py         # أدوات مشتركة (تحويل نص السعر لرقم..)
│       ├── noon.py
│       ├── amazon_sa.py
│       └── extra.py
├── data/                   # "قاعدة البيانات" (JSON) — يحدّثها الـ workflow
├── .github/workflows/
│   └── price-check.yml     # الجدولة + التشغيل
└── requirements.txt
```

## كيف تضيف متجر جديد أو تعدّل واحد موجود
كل متجر عبارة عن ملف بسيط داخل `bot/scrapers/` فيه دالة وحدة اسمها
`search(query)` ترجع قائمة من `{"title", "price", "url"}`. أنشئ ملف
جديد بنفس الشكل، واستورده وسجّله في `bot/scrapers/__init__.py`
داخل قائمة `STORES`. باقي الكود يتعامل معه تلقائياً.

## نقاط ضعف مهمة (اقرأها قبل ما تعتمد عليه)

1. **السكرابنق هش بطبيعته.** أي متجر يغيّر تصميم صفحاته، السكرابر
   حقه ممكن يتوقف عن الرجوع بنتائج. جهّزت الكود يفشل بهدوء (يرجع
   قائمة فاضية بدل ما يطيح كل السكريبت)، بس هذا يعني إنك أحياناً ما
   بتوصلك تنبيهات وما بتعرف السبب إلا لو راجعت logs الـ Actions.
2. **أمازون تحديداً غير موثوق.** أمازون من أشد المواقع في كشف
   البوتات، وممكن يرجع صفحة كابتشا بدل النتائج الحقيقية، خصوصاً من
   IP مشترك زي اللي تستخدمه GitHub Actions. اعتبر نتائجه "بونص" مو
   مصدر أساسي.
3. **مطابقة المنتج تقريبية.** البحث نصي بسيط (اسم المنتج زي ما
   كتبته) — ما فيه تأكد إن "أرخص نتيجة" هي فعلاً نفس الموديل/السعة
   اللي تقصدها بالضبط (ممكن يرجع لك سعر إكسسوار أو موديل ثاني رخيص
   إذا الاسم عام). كل ما كان اسم المنتج اللي تكتبه دقيق أكثر (يشمل
   السعة، اللون، الخ)، كانت النتائج أدق.
4. **حدود GitHub Actions المجانية.** إذا خليت الريبو Private
   (خاص)، عندك 2000 دقيقة مجانية بالشهر بس — يفي بالغرض لو ما زودت
   تكرار الفحص كثير. لو خليته Public، ما فيه حد تقريباً.
5. **قانونياً/أخلاقياً:** السكرابنق بشكل عام قد يخالف شروط استخدام
   بعض المواقع حتى لو الاستخدام شخصي وبدون ضرر. هذا المشروع مبني
   لاستخدام شخصي خفيف (فحص كل 30 دقيقة لمنتجات قليلة) وليس Scraping
   تجاري أو مكثف.
6. **الجدولة قد "تنام".** GitHub يوقف أحياناً scheduled workflows
   في الريبوهات الخاملة — راجع قسم "تأكد إن الجدولة شغالة" بالأعلى.

### رأيي الصادق
الفكرة نفسها منطقية ومفيدة، وطريقة GitHub Actions + JSON هي فعلاً
أبسط حل مجاني بدون سيرفر لمشروع بهذا الحجم. لكن السكرابنق (خصوصاً
أمازون) هو أضعف حلقة، وبيحتاج صيانة دورية بسيطة كل ما موقع غيّر
تصميمه. لو الهدف "تتبع منتج أو اثنين بشكل غير رسمي وبدون ضغط"، هذا
الحل يستاهل. لو الهدف موثوقية عالية على نطاق واسع (عشرات المنتجات،
تنبيه فوري خلال ثواني)، فالبديل الأذكى يكون: استخدام خدمة مقارنة
أسعار جاهزة تدعم السعودية (إن وجدت واحدة موثوقة تناسبك) بدل بناء
سكرابر خاص، أو الانتقال لبنية webhook (سيرفرلس مجاني زي Cloudflare
Workers) للأوامر + GitHub Actions للفحص الدوري — لكن هذا يعقّد
الصيانة اللي طلبت إنها تكون بسيطة، فما رشحته كخيار افتراضي.
